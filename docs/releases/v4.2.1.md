# Konoha 4.2.1 — Natural Repository Study Conversations

This is the v4.2.1 release package/document. Git tag creation, push and any
GitHub Release remain separate maintainer operations and are not implied or
authorized by this document.

This is a patch release on top of v4.2.0. It contains one coherent correction
to repository-study conversations and adds no new feature milestone.

This is a new post-v4.2.0 release. It is distinct from the earlier internal
v4.2.1 engineering package label (supervised recommendations and
public-repository learning), which was never released separately and shipped
inside v4.2.0.

## Problem

A natural Spanish or multiline request such as “Mirá este repositorio y
explicame…” could fall through into normal mission planning instead of
repository comprehension. A novice asking to understand the repository was
sent toward provider-backed planning rather than the existing evidence-backed
study.

## Fix

- Deterministic, conservative repository-study intent recognition for natural
  English and Spanish requests, including multiline turns submitted with
  `:fin`. Recognition uses fixed word families matched on accent-stripped,
  casefolded tokens. Exact commands remain single-line; a multiline turn
  reaches only the conservative natural-language families, never a command
  keyword embedded inside it.
- Active-study natural continuation: while a study is active, natural
  clarification requests, evidence requests (“Mostrame de dónde sacaste…”) and
  acknowledgements continue that study through the same canonical study and
  teachback APIs.
- Evidence-backed novice explanation: plain-language answers cite the retained
  README lines they are based on, report missing evidence as missing, and
  distinguish this terminal's own gates from what the repository documents.
- Root README purpose evidence: ordinary prose of the repository-root
  `README.md` is retained as purpose evidence. Other Markdown, nested READMEs
  included, keeps the previous command/flag-like line extraction.
- Exact frozen user journey regression: a separate-process terminal journey
  replays the frozen novice turns byte-for-byte, verified by SHA-256, and
  checks that the conversation stays in one study, cites the README, closes
  only on `:entendido`, leaves the repository unchanged and creates no mission
  or context-acquisition state.

## Safety and authority

- No LLM intent classifier was added; intent recognition is deterministic.
- A request to change, fix, add, run or otherwise act on something still
  routes to a normal supervised mission, even when it mentions the
  repository.
- Repository-study turns do not invoke providers or mission planning.
- Repository study does not grant authority.
- Ordinary acknowledgements (for example “ok, gracias”) do not close
  teachback. Only the exact single line `:entendido` closes repository
  understanding, and that closure grants no execution approval.
- No schema, provider, approval, execution or doctrine change is included.

## Compatibility

- No MissionPlan, ExecutionState or repository study schema change relative
  to v4.2.0.
- Studies of repositories whose root README contains ordinary prose retain
  more documentation lines as evidence than in v4.2.0.
- Exact `:repo …` commands, `:entendido`, `--plan-only` and `--resume`
  semantics are unchanged.

## Verification

- The exact frozen novice replay was recorded as 14/14 PASS for the bugfix.
- The 15-suite regression run recorded for the bugfix does not by itself
  verify this release. This document does not record release test results;
  the 15-suite regression must be rerun on the release commit as part of the
  separate review and release gates.

## Known limitations

- Intent recognition is intentionally conservative and word-list based;
  natural phrasings outside its families fall through to the normal mission
  flow, which keeps its own approval gates.
- Novice explanations are limited to what the retained root README states;
  the study does not verify that documentation is true.
- Known limitations carried over from v4.2.0 (see
  `docs/releases/v4.2.0.md`) remain unresolved.
