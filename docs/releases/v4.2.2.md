# Konoha 4.2.2 — Canonical Full-Repository Test Gate

This is the v4.2.2 release package/document. Git tag creation, push and any
GitHub Release remain separate maintainer operations and are not implied or
authorized by this document.

This is a patch release on top of v4.2.1. It corrects how continuous
integration and release readiness execute the whole repository test suite,
and repairs the test defects that the corrected gate exposed. It adds no
feature and changes no product behavior.

## Problem

- Whole-repository test execution in CI and in release readiness relied on
  root `unittest` discovery (`python -m unittest discover -s tests`).
- Most repository suites live in immediate directories under `tests/` that
  are not Python packages, so root discovery does not descend into them.
- The old gate therefore silently exercised only a small subset of the
  repository's tests (13 tests from 2 of 58 immediate suite directories)
  while still reporting success.

## Correction

- CI and release readiness delegate whole-repository discovery to
  `tools/release_testing/run_release_tests.py`.
- That canonical runner is the single whole-suite discovery implementation;
  no second discovery path is maintained.
- Each suite executes independently.
- Later suites continue to execute after an earlier suite fails.
- The aggregate status fails when any suite fails.

## Exposed debt

Running every suite revealed two previously hidden test defects:

- A stale CLI test still expected version `4.0.0` instead of the current
  release contract.
- Deterministic orchestration (Hokage) test fixtures were coupled to live
  provider and hardware readiness during bootstrap, so their outcome depended
  on the machine running them.

## Remediation

Both defects were corrected as test defects only:

- The CLI test checks the current canonical version metadata and the actual
  `--version` behavior instead of a hardcoded release number.
- Deterministic orchestration tests use scoped synthetic provider evidence.
- Real `ProviderSelectionError` behavior remains tested.
- No production behavior changed.

## Safety and authority

- No suite is excluded from the gate.
- No skip or `expectedFailure` was added to obtain a passing result.
- `ProviderSelectionError` was not weakened.
- Deterministic tests require no real provider, network access or
  credentials.
- No approval, teachback, evidence or runtime authority change is included.

## Compatibility

- No CLI, schema, provider, approval, execution or doctrine change relative
  to v4.2.1.
- The canonical runner can still be run directly; it is now also the
  whole-repository step of CI and release readiness.

## Verification

- The full canonical gate was recorded for the engineering changes as 58
  suites discovered and executed, 1243 tests, with 0 failures, 0 errors,
  0 skips and 0 timeouts.
- That engineering result does not by itself verify this release. This
  document does not record release test results; the full canonical gate and
  the 15-suite release regression must be rerun on the release commit as part
  of the separate review and release gates.

## Known limitations

- Known limitations carried over from v4.2.1 and v4.2.0 (see
  `docs/releases/v4.2.1.md` and `docs/releases/v4.2.0.md`) remain
  unresolved.
